# AI Prompt 与问题解决记录

本文件整理使用 AI 辅助开发时的提问方向，以及开发中遇到的问题。下面的提示词是按开发阶段归纳的简化示例，不是逐字对话记录。

## 需求输入

用户提供的笔试要求：从零实现最小 Agent，不能使用现有 Agent 框架；至少三个工具且必须含 todo；支持独立 session、持续对话与工具追问、上下文压缩、最大轮次、异常处理与 trace；提供测试、README 和 AI 使用记录。架构题每模块选一道，放在 docs。用户随后明确指定使用 DeepSeek。

实现范围取为 Python CLI，不增加 Web UI 或服务。两个终端使用不同 session ID 对应两个聊天窗口。

## 开发提示词（简化示例）

| 阶段 | 提示词示例 |
| --- | --- |
| 需求拆解 | “根据题目梳理一个最小实现方案，说明 Agent 循环、工具调用和 session 如何配合。核心流程自行实现，不依赖现成 Agent 框架，先提供命令行入口。” |
| 工具实现 | “实现 calculator、search 和 todo，search 可以 mock。工具统一注册并声明参数，由模型决定调用哪个工具。执行前检查参数，todo 的状态需要持久化，关键逻辑加必要注释。” |
| 模型接入 | “接入 DeepSeek 的真实 API，区分直接回答和工具调用，并把工具执行结果传回模型继续判断。补上请求超时和基本错误处理，密钥通过本地配置读取。” |
| 会话管理 | “同一个用户的不同窗口应对应独立 session，聊天记录和待办都要隔离。重新启动后，可以通过原来的 session 继续对话。” |
| 上下文管理 | “支持普通追问和基于工具结果的追问，保留必要的历史信息。历史过长时做基础摘要压缩，注意工具调用与结果的完整性，同时限制单次请求的最大循环次数。” |
| 测试验证 | “按题目整理测试场景，覆盖正常对话、多步工具调用、会话隔离、历史恢复和主要异常。区分本地自动化测试与真实 API 验收，检查实际执行结果和保存的状态。” |
| 文档整理 | “README 说明运行方式、模块职责，以及 memory 何时召回、放在哪里。架构题每个模块选一道，放到 docs 中，说明设计取舍，区分已实现功能和扩展方案。” |
| 最终复核 | “逐项对照题目检查实现和测试，重点检查连续对话、上下文压缩和工具循环衔接时是否有遗漏。列出已验证的内容、未验证项和需要修复的问题。” |

提示词主要说明目标和范围，具体实现细节在开发、测试和复核时逐步确定。下面记录实际遇到的问题及处理方式。

## 关键问题与处理

### 1. “从零”不等于重写 HTTP 和 JSON Schema

自研部分是运行循环、状态保存、工具协议处理和上下文策略。仅使用底层通用库处理 HTTP、Schema、本地环境文件和跨平台锁，避免把 Agent 主流程委托给现成框架。

### 2. DeepSeek 的思考字段不能想当然丢弃

核对官方文档后，默认采用非思考模式；解析器仍识别并保留服务商返回的 `reasoning_content`，避免不完整回传。CLI/trace 不显示思考正文，摘要也不把思考当成事实。依据：[工具调用](https://api-docs.deepseek.com/guides/tool_calls/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

### 3. session 隔离必须落实到存储和工具

只给聊天历史添加 session ID 不够，todo 和摘要也必须按 `(user_id, session_id)` 查询。模型不能在工具参数中选择别人的会话。文件锁只锁当前 scope，避免持有 SQLite 写锁等待模型、导致全部窗口阻塞。

### 4. 压缩不是直接截断消息列表

任意裁切容易留下孤立的 tool 结果。以完整用户交互为单位压缩，单独保存摘要及已覆盖的 turn ID；数据库中的原始记录仍在。摘要失败或输入被截取时明确标记损失，todo 的准确状态来自数据库。

### 5. 中断与重试不能重复产生副作用

在调用前保存计划，工具执行后保存结果。崩溃时“副作用已经发生、结果尚未落库”的窗口无法靠提示词消除，因此恢复时不自动重试，标记结果未知并先查询状态。todo 新增对同名未完成项去重；不对任意工具承诺 exactly-once。

### 6. 复核发现待办长列表丢失可达性

初版通用工具结果上限为 8000 字节，超出时只给预览。独立审阅用 20 条合法长标题复现：最后面的待办被截掉，反复 list 仍看不到，模型无法按内容找到其 ID。

修复为 todo list 游标分页，每页最多 5 项，返回 `items` 和 `next_cursor`；新增多页测试，用 100 条长标题验证末项可取回、每页不触发结果截断。CLI 的 `/todos` 仍直接查看本地完整列表。这个问题不能靠“让模型更仔细”解决，需要调整工具契约。

### 7. 测试通过不等于真实模型已经验收

HTTP 协议测试与 runtime 行为测试使用明确的测试替身；运行入口连接真实 DeepSeek。另提供显式开启的 live 用例。开发环境未提供 API 密钥时，live 用例跳过，不能把离线结果写成真实 API 成功。

用户补充本地密钥后，实际执行两个小型真实 DeepSeek 用例并通过。进一步审阅时强化了 live 断言：不能仅凭“工具执行过”判断成功，必须检查 search 的成功结果与 mock 标识、calculator 的数值、todo 的真实状态；也不能仅凭第二个会话的数据库为空推定隔离成功，必须确认实际调用 todo.list、返回空 items，且发送给模型的上下文没有第一会话的内容。另验证纯对话重启追问与真实摘要后的事实保留，长历史使用明确标注的合成夹具。详见 `docs/acceptance.md`。

### 8. 跨模块复核发现压缩后工具循环提前终止

初版仅在一次用户请求开始时压缩历史。独立复核用真实 SQLite 和脚本化模型复现：默认 32,000 字节预算下，20 个旧交互压缩后占用 31,999 字节；calculator 执行成功，但回填结果使下一次请求超限，Agent 提前结束，虽然旧历史仍可继续压缩。原来的 context 和 runtime 测试分别通过，无法发现这一组合路径。

先新增失败回归，再修改为每次模型决策前若发现超预算，就重新构建上下文：优先缩短当次注入的摘要，必要时在本地摘录旧的完整交互，不追加模型摘要请求，不裁切当前工具调用与结果。回归覆盖 20/200 轮持久历史、首次工具后才超限，以及当前交互本身确实放不下时明确停止。对多模块交互应检查实际执行链，而不能只累计单元测试数量。

## 未纳入最小实现的内容

真实搜索、天气、多模态、流式输出、长期记忆检索、异步工具队列、定时任务、生产身份认证及分布式调度。它们不是本次基础题的必需实现，也没有为它们预先搭建复杂框架。
